# IMDerivatives research record

Project evidence reviewed 28 September 2026 (UTC); market data added 29 September 2026 (UTC). This is a static, bounded research snapshot, not an audit or a live security monitor. No wallet was connected and no transaction was submitted. The structured record, including claim-level citations and exact addresses, is [src/data/projects.json](src/data/projects.json); the market-data snapshot is [src/data/market.json](src/data/market.json). The export also includes `projects.json` and `market.json`.

## Method and scope

Read project pages, project documentation, the IMD homepage and documentation, indexed on-chain announcements, and relevant marketplace records. Loaded Nosh and Hive in a browser because their initial HTML did not contain the complete rendered state. Read Hive's public configuration and Nosh's registry API. Searched `imd.fun` and `identity.md` for the four project names; no explicit endorsement was returned. Searches and absence from these pages cannot establish universal absence.

`VERIFIED FACT` means a narrow directly observed or corroborated fact, such as what a page identifies. It does not convert the page's economic, custody or security claims into verified contract behavior. Project statements, third-party reports, automated warnings and unknowns are labeled separately. A reported address is not the same as verified source code. None of these listings establishes official IMD affiliation.

Direct Etherscan address fetches returned HTTP 403 for Swarm Pepe and TokenWorks. The Swarm Pepe Etherscan browser visit also returned 403. Ethereum Blockscout address API requests and the Nosh Robinhood Blockscout address API request returned 403 during the 28 September review. Read-only RPC attempts (`eth_chainId`, `eth_getCode`, `eth_call` for name/symbol/owner) to Ethereum PublicNode and the Robinhood public RPC returned 403. No bytecode verification, transaction receipt validation, owner privilege analysis or audit conclusion is claimed on that basis. The 29 September market-data pass reached the Ethereum Blockscout *token* endpoint (see below); Robinhood Blockscout still answered with a Cloudflare challenge.

## Market data (added 29 September 2026)

Every market figure on the site is a **THIRD-PARTY CLAIM** by the named aggregator about recent trading activity. It is never a verified fact about the contract, its safety, custody or affiliation, and it is never an endorsement or investment recommendation. Snapshot generated at **2026-09-29T17:09:45Z** by `scripts/fetch-market.mjs`, normalised by `src/market/normalize.mjs`, committed as `src/data/market.json`, and exported as `dist/market.json`. The production build never fetches anything; visitors can optionally press "Refresh from DexScreener", which repeats the same contract-keyed DexScreener requests in their browser (public API, no key, no wallet) and applies the same normalisation.

### Identification and definitions

- **Identification is by chain + contract address only.** For tokens, the request is DexScreener `GET /token-pairs/v1/{chain}/{contract}` and only pairs whose `baseToken.address` equals the listed contract on that chain are counted. Name and symbol matching is never used. Name collisions exist: a DexScreener search for "IMDSTRTGY" also returns an unrelated same-named token on BNB Chain at `0x35E1D2De2bcFF07fF37C4485b9fe5c61C01F4c9C`; it is excluded because it is a different contract on a different chain. `scripts/check-data.mjs` asserts that each market contract is one of the project's listed contracts on the same chain.
- **Price, 24h change and market cap** come from the single most liquid matched pair (DexScreener `liquidity.usd`). Thin secondary pools on Robinhood Chain quote noticeably different prices; they are not averaged in.
- **Market cap is DERIVED, not reported.** For all three tokens DexScreener's `marketCap` equals its `fdv` (price × total supply, fully diluted). No source reports a verified circulating supply, so **circulating supply is N/A** and no circulating-supply market cap is computed. The three token values are comparable with each other because they use the same method from the same source; the chart is labeled accordingly.
- **24h volume (token)** is the sum of DexScreener `volume.h24` in USD across all matched pairs on that chain. This is DEX trading volume only.
- **24h volume (NFT)** is OpenSea's `one_day` marketplace sales volume for the collection, in ETH. It is a different metric, shown separately on the Swarm Pepe card and detail view, and **never added** to the 24h tracked volume total. No TVL figure is used anywhere.
- **Totals.** Tracked market cap = sum of comparable token market caps (3 projects). 24h tracked volume = sum of token DEX volumes (3 projects). Chart shares = project market cap ÷ tracked total, computed at render time from the data; N/A projects are excluded from the denominator. Rounded shares sum to 100.1% (rounding), checked by `scripts/check-data.mjs`.
- **N/A** means the metric could not be reliably obtained. Nothing is estimated to fill the interface.

### Refresh, provenance and re-verification

- To refresh the committed snapshot: `node scripts/fetch-market.mjs` (needs network), then `node scripts/check-data.mjs`, then rebuild. The script records `generatedAt`, per-project `marketDataUpdatedAt`, the exact API URL, the identification rule, the primary pool and any error. Failed fetches are written as nulls with the error text, never as stale or invented numbers.
- To reproduce a figure: request the recorded `marketDataSource.api` URL and apply the rules above (most liquid pair for price, sum of `volume.h24` for volume). Aggregator values move continuously, so a later request will not return the snapshot numbers exactly; the recipe, not the number, is what is reproducible.
- Link check on 29 September 2026: the API URLs recorded above answered HTTP 200 from the seat; the human-facing DexScreener and OpenSea page links answered HTTP 403 to a non-browser client (bot protection), as Etherscan did during the 28 September review. The page URLs are the ones DexScreener's API returns in its `url` field, or OpenSea's canonical collection path; they were not opened in a browser with internet access.
- The in-browser refresh sends requests only when a visitor presses the button, and only to `api.dexscreener.com`. It is not started automatically, uses no key and stores nothing. If it fails, the site says so and keeps the snapshot. The NFT figures are never refreshed in the browser.
